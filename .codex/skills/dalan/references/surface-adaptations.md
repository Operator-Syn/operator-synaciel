# Surface adaptations

Dalan is a visual grammar, not a portfolio template. Keep the shared vocabulary—hierarchy, type contrast, visible alignment, warm signal color, technical notation, and restrained motion—then change the composition to serve the surface's task.

## Portfolio

Prioritize identity, work discovery, case-study pacing, and a memorable closing action. Let display type and project sequencing carry the personality. Use indexed labels and diagrams as narrative devices, not as fake product telemetry. A one-page flow is useful when the work is few and the story is strong; use separate routes when comparison or deep reading matters.

## Landing page

Prioritize comprehension and conversion before atmosphere. Establish the promise, proof, primary action, and objection-handling order in the first meaningful viewport or two. Keep the Dalan treatment in the type, rules, section rhythm, and accent logic; do not let a decorative hero delay the value proposition.

## Dashboard

Prioritize scanability, status, density control, and repeated actions. Use the dark field and technical notation to support real metrics, filters, timelines, and states. Reduce oversized display type after the entry point; preserve compact utility type and alignment anchors. Make active, loading, empty, error, permission, and stale-data states explicit.

## Product surface

Prioritize task completion, orientation, feedback, and recovery. Use editorial emphasis for page titles and meaningful milestones, not for every control. Keep forms, tables, dialogs, navigation, and validation conventional enough to be learned quickly. Let the distinctive identity appear in the shell, type roles, borders, status marks, and one controlled motif.

## Mixed surface

When a page combines marketing and application behavior, separate the modes visibly. Give the narrative area more expressive scale and the working area more predictable density. Do not make a user complete an operational task through a portfolio-style interaction merely to preserve visual continuity.

## Density test

Ask what the user is doing every five seconds. If the answer is “reading a story,” allow more space and sequencing. If the answer is “comparing, deciding, or operating,” tighten the rhythm, expose state, and reduce ornament. The same palette and rules can survive both; the same spacing and type scale cannot.
