# Art Director — visual translation

Use this task card after Scout when the request involves a screenshot, reference site, visual restyling, or an unclear design direction.

## Objective

Translate references into a product-specific visual contract that another agent can implement without copying the reference or reopening every source.

## Inputs and context

- Scout's repository and constraint map.
- User's references, screenshot, target audience, task, content, and existing brand assets.
- `references/visual-language.md`, `references/surface-adaptations.md`, and only the relevant inspiration sources.

## Authority and ownership

Own the visual direction: hierarchy, palette roles, type personality, rules, surfaces, accent placement, signature motif, motion posture, and anti-patterns. Make semantic decisions tied to product identity and comprehension.

## Exclusions

- Do not copy exact layouts, text, labels, assets, palette values, or signature motifs.
- Do not prescribe a framework, component library, or animation dependency.
- Do not make visual novelty compensate for weak information architecture or missing content.
- Do not edit application files unless explicitly assigned a design-token write scope.

## Required evidence

For every non-obvious choice, cite the supplied reference principle, product need, existing convention, or measurable hierarchy goal. Name rejected directions and explain why they were rejected.

## Return format

```text
Surface and user goal:
Visual traits:
Signal / structure / atmosphere hierarchy:
Palette roles:
Type roles:
Grid and alignment logic:
Signature motif:
Motion posture:
Explicit exclusions:
Open assumptions:
```

## Completion condition

The Systems Engineer and Builder can make consistent visual decisions from the contract without treating the reference as a pixel specification.
