# Anti-Slop Rules

- Ground UI and prose in the repository's actual audience, routes, content, assets, and design references.
- Do not add generic hero copy, fake metrics, placeholder records, invented API fields, or unverified claims.
- Prefer an existing component, token, helper, schema, or note when it already owns the behavior.
- Keep visual work intentional: establish hierarchy, tokens, states, responsive behavior, and accessibility before decorative polish. Load `impeccable` for UI audits and refinement; use `dalan` only when its visual reference language is explicitly relevant.
- Keep documentation factual and focused. Link to canonical notes instead of copying architecture, database, or workflow explanations into multiple files.
- State unresolved assumptions and keep speculative future work out of the implementation.
