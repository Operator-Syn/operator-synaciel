# Operator-Synaciel repository map

Syn-Forge is a TypeScript npm monorepo: React/Vite/Tailwind on Cloudflare Pages, Hono and other TypeScript Workers, D1/R2 persistence, and an Agents SDK Durable Object for the assistant. Node-based tests run through tsx; browser specs use Playwright. The root and workspace manifests define commands; Wrangler config and the checked-in workflow define runtime and release wiring.

Use the table to find the owner. Then pick one playbook for substantial work, adding a second only if your change crosses its boundary:

- [Web and Portfolio API](web-and-api.md): follow a user-visible route, Pages behavior, a content response, or a storage change down to its owning checks.
- [Public MCP, authentication, and assistant](assistant-and-mcp.md): distinguish the public read-only protocol, the session gateway, and the private stateful assistant before tracing a failure or change.
- [Delivery, verification, and interrupted-work recovery](delivery-and-recovery.md): establish the revision and local overlap, choose the right verification tier, or trace a CI or release decision.

The map and playbook tables use backticks for literal repository-relative paths, with `/` at the end of directory paths. The checker validates those paths against the working tree.

## Boundaries to preserve

- The public MCP and public-auth Workers serve different contracts. Public MCP reads published data through the API adapter; the browser assistant goes through public-auth's session and ownership checks before reaching the private assistant Worker. Keep API private writes behind the server-held admin boundary.
- Test suites belong to their workspace. A test-only change should not select a deploy or add test-fixture classes to production CSS; the detector fixtures and Tailwind entry stylesheet are the places to verify those exclusions.
- Product and design inputs live under `docs/` for the bundled design tooling. Browser auth and run artifacts are local and ignored; read the Playwright config and observability helper, not saved credentials or traces.
- A plan, dated check, or deploy workflow definition is not evidence that a release ran. Remote deployment, migration application, and credential use are separate from routine orientation.
